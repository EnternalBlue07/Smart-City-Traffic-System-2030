MACHINE LEARNING APPROACH:
-------------------------------------
Algorithm: Historical Pattern Matching (Statistical ML)

Method:
  1. Collect violations by hour/day from database
  2. Match current time to similar historical periods
  3. Calculate average violations for pattern
  4. Classify density using tunable thresholds
  5. Recommend cycle time based on density + congestion

Thresholds (Tunable):
  < 3 violations   → LOW density      → 45s cycle
  < 7 violations   → MEDIUM density   → 60s cycle
  < 15 violations  → HIGH density     → 75s cycle
  ≥ 15 violations  → VERY HIGH density → 90s cycle

Congestion Detection:
  Recent (15 min) > 2x Historical Avg → CONGESTED
  Ratio 2.0-2.5 → MODERATE
  Ratio 2.5-3.0 → HIGH
  Ratio ≥ 3.0   → SEVERE

Why Not Deep Learning:
  ✓ Speed: Instant predictions (< 100ms)
  ✓ Interpretability: Operators understand logic
  ✓ Low data requirements: Works with limited history
  ✓ No training: Ready immediately after deployment
  ✓ Explainable: Clear reasoning for recommendations

TROUBLESHOOTING:
-------------------------------------
Issue: "Insufficient data" predictions
  → Run seed_demo.py to populate violations
  → Wait for real violations to accumulate
  → Temporarily lower min_data_points (testing only)

Issue: Low confidence scores
  → Need more historical data (7+ days recommended)
  → Violations too sparse (need regular patterns)
  → High variance in traffic (expected in some areas)

Issue: Incorrect density classification
  → Adjust thresholds in traffic_prediction.py
  → Verify violation data accuracy
  → Check if patterns match actual local traffic

Issue: Optimization not improving flow
  → Thresholds may need tuning for local conditions
  → Monitor over longer period (weeks, not hours)
  → Consider rush hour vs off-peak separately
